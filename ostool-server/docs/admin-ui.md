# 管理界面与事件协议

## 前台个人工作台

网站与管理后台使用独立布局和路由：网站首页 `/`，个人工作台 `/account/*`，
管理后台 `/qcl/*`。公网版共享服务器账号与 CLI 登录协议；普通成员不能访问管理 API。本地版免登录。
前台、个人工作台和后台的未知页面使用统一的 404 组件，沿用当前明暗主题与各自布局，
提供返回入口和返回上一页操作。直接访问未知页面时，服务器返回 HTTP 404；
未知 API 与静态资源继续使用接口错误或资源错误响应。新增页面路由时，同步更新
`ostool-server/src/static_assets.rs` 中的页面路径判定，确保刷新页面时状态码正确。
前台登录默认进入 `/account`，管理员从网站登录也不会自动跳转后台；只有访问后台时的
站内 `redirect=/qcl/...` 才会在验证管理员身份后返回对应管理页面。

前台顶部左侧 LOGO 与菜单紧邻，右侧为主题图标和登录/注册；
登录后显示头像菜单。主题支持明亮、黑暗和跟随系统，前台独立使用 `ostool.web.theme`
保存偏好，后台仍使用 `ostool.admin.theme`。移动端保留主题按钮并提供折叠菜单。

所有前台页面（包括 `/login`、`/register`、`/password-reset`、`/rental-request`）统一使用网站顶部导航和公共页脚。登录、注册、找回密码与租赁申请保留一屏高度的中间工作区，页脚紧随其后并可通过页面滚动到达。登录、注册和找回密码共用左侧介绍与右侧表单布局，只切换右侧内容；桌面内容居中占屏幕宽度的 80%，手机或低高度窗口的表单可内部滚动。后台 `/qcl/login` 保留独立全屏布局。
前后台登录的身份字段统一标为“账号”，支持用户名或邮箱；认证表单输入框上方的字段标题加粗显示。
前后台登录及注册各步骤均显示默认未勾选的协议复选框，勾选同意用户协议和隐私政策后才可提交；协议版本更新后需重新勾选。复选框与正文同行，文本可在窄屏自然换行；验证码图片嵌入输入框右侧，可点击刷新。
页面停留或输入期间不会自动换图或清空答案；图形验证码过期仍由服务端拒绝，点击图片可获取新的验证码。
前后台保持独立入口、登录会话和主题偏好，共用登录布局与验证码组件。
前后台登录页始终提供“忘记密码？”入口。用户填写注册邮箱并完成人机验证后发送密码重置邮件，点击邮件中的一次性链接设置新密码；不再要求手动输入邮件验证码。链接过期或已使用时可重新发送，成功后撤销旧登录和访问令牌，保留双重验证设置。后台必须配置邮件服务并开启密码找回；未配置时页面提示联系管理员。
页面标题根据内容区域宽度自然换行，不通过手动换行或将强调文字设为块元素来固定断行位置。

公开版个人工作台包括总览、基本信息、账号安全、我的租赁、租赁申请和个人访问令牌。侧栏与账号菜单分别提供“我的租赁”和“租赁申请”入口；前者展示正式租赁记录，后者展示申请进度、审核结果及撤回操作。
设备页无需登录即可用卡片浏览、搜索全部已配置设备，禁用设备保留显示且不可申请。公开 SSE 仅返回站点信息和设备白名单字段；登录后才能申请租赁。本地版展示设备目录，免登录且不提供用户租赁入口。基本信息可修改显示名称和邮箱，修改邮箱需验证
当前密码。改密验证旧密码后撤销该账号全部 OAuth 登录、个人访问令牌及已授权设备码，
随后回到网站登录页。已有编辑草稿不会被实时推送覆盖。

申请与正式租赁分开存储。成员提交申请后可在待审核状态撤回；管理员通过后台
“租赁管理 → 租赁申请”批准或拒绝，并可填写审核意见；列表将状态与审核意见分列展示。批准在同一个数据库事务内
重新检查账号、板卡和租赁时间冲突，生成正式租赁并记录审批结果；重复或并发批准不会
生成重复租赁。申请本身不占用时段、不上电、不授予板卡使用权。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/account` | 当前用户资料、可申请设备目录、租赁/申请数量汇总和令牌元数据 |
| `GET /api/v1/account/rentals` | 当前用户租赁的数据库分页结果 |
| `GET /api/v1/account/rental-requests` | 当前用户申请的数据库分页结果 |
| `GET /api/v1/account/availability` | 按 `board`、`from`、`to` 查询匿名占用，最多一年 |
| `GET /api/v1/account/events` | 当前用户实时投影，使用独立浏览器会话，CLI 令牌不可访问，URL 不携带令牌 |
| `PUT /api/v1/account/profile` | `{email, display_name, current_password?}` |
| `POST /api/v1/account/password` | `{current_password, new_password}` |
| `POST /api/v1/account/rental-requests` | `{board_id, starts_at, ends_at, notes?}` |
| `DELETE /api/v1/account/rental-requests/{id}` | 撤回自己的待审核申请 |
| `GET /api/v1/admin/rental-requests` | 管理员申请分页列表，通过 `listing` topic 同步 |
| `POST /api/v1/admin/rental-requests/{id}/review` | `{decision: "approve" \| "reject", note?}` |

前台页面统一使用 `api/events.ts` 中的独立 account store，连接个人 SSE；不订阅管理 SSE，
不在提交后全量 GET，也不轮询列表。个人推送始终按认证用户过滤，并移除管理投影中的
用户列表、硬件控制命令、服务器配置和其他人的租赁详情。日历新增 `availability` 投影，
仅包含已占用的开发板、起止时间与记录 ID，不包含其他用户的身份、申请说明或租赁备注。
令牌只在创建响应中展示一次，
列表仅包含名称和时间等元数据。切换账号会清理旧的投影并重新连接。

本地版免登录，不提供个人工作台、用户申请和审批管理。
租赁申请由统一 SQLx 初始迁移创建，不包含启动时旧数据搬运。

源码改动后，执行 `scripts/dev.sh restart` 重新构建 Docker 发行版镜像并替换运行容器。
HTML 响应使用 `Cache-Control: no-store`，带内容哈希的静态资源可长期缓存。
使用 `OSTOOL_SERVER_WEB_DIST_DIR` 提供预构建资源时，其环境变量和目录变化也会触发构建。
开发环境由 Docker Compose 管理，`status` 查看容器状态，`stop` 停止容器并保留数据卷。

## 操作流程

管理列表操作列最多显示三个图标按钮，常用操作直接展示，其余收进“更多”；不为不存在的功能显示占位按钮；权限不足的操作隐藏。会话历史将状态与结束原因分列展示，仅提供详情、查看对应开发板和删除；删除仅针对已结束记录并要求会话管理权限。租赁列表没有启停操作，仅可修改仍有效的预约租赁。
租赁申请的待审核行直接展示同意、拒绝及更多；会话列表直接展示释放、强制释放及更多；历史直接展示详情、删除及更多。租赁固定展示编辑、取消及更多，已结束或已取消的记录禁用编辑和取消按钮，以保持各行对齐；即时使用租赁禁用编辑。删除与会话释放仍需确认。
开发板可跳转到按设备筛选的会话和租赁、设备文档；用户和角色可跳转至关联租赁、角色或用户列表。
新建开发板底部的“复制已有数据”弹出已有开发板选择框，确认后替换表单草稿，ID 清空；列表“基于此新建”使用相同流程。
串口、MAC、启动和电源配置会一并复制，保存前需确认新设备绑定；设备认证需单独配置，公网 HTTPboot 新板仍先禁用保存。
复制不会自动保存，后续实时推送不会覆盖复制后编辑的草稿。

公共表现统一由组件层维护：`PagePanel` 负责页面滚动区和固定底栏，`ListToolbar`、
`DataTable` 和分页组件负责列表；`Section` 使用 `FormGrid` 排列表单，后台默认三列，
需要两列的窄内容区显式传入 `columns={2}`，长字段使用 `fullWidth`。原生表单可用
`FormGrid asChild` 保留表单语义，重复的字段行使用 `FormRow`，不再按页面名称覆盖网格。
`EditorFooter` 统一状态和操作区，`ReloadNotice` 统一草稿冲突后的载入操作，载入按钮
不会触发表单提交。字段宽度、列表类型等展示差异声明在字段配置中，页面只负责业务数据、
权限、校验和保存行为；不新增依赖后台容器或字段名推断布局的 CSS 分支。

本地版和公网版统一使用 PostgreSQL 存储板卡、DTB 内容、OTA 镜像/任务/观察记录，
以及后台可编辑的网络、TFTP、上传设置。公网版启用账号、授权和租赁功能，本地版不启用这些功能，
公网前后台和 CLI 要求登录并校验角色/租赁。没有数据库连接时，常规服务器
启动会直接报错，不会回退到另一套文件存储。部署启动参数从选定的 `.env` 及进程环境读取，
会话文件内容分块入库；磁盘仅用于暂存与可重建串口缓存，实时硬件连接按生命周期管理。服务器不再读取旧业务文件；
已有开发板只通过独立迁移工具手动导入，操作说明见下文。

新增开发板时，ID 不得为 `new`（不区分大小写）、`.` 或 `..`。通信串口和继电器控制端口只在启用的开发板配置间互斥（含同一设备的别名）；禁用配置不占用端口，可共享保存。启用时重新校验占用方，冲突会提示开发板 ID 并进入修改页；
服务器会检查相同稳定标识，并在设备可解析时检查不同别名是否指向同一串口。
离线且无法解析的不同别名不能证明等价，应统一使用同一稳定标识。
启用 U-Boot 板卡前必须配置串口；未完成配置可勾选“禁用开发板”保存。
未启用设备 UDP 发现时，公网 HTTPboot 板卡新增后禁用：保存板卡 → 保存固定设备地址 → 取消禁用并保存。
启用内网 UDP 发现时可按已配置的 MAC 接入设备，无需预先配置证书或凭据。固定地址在启用时检查配置可读取，不要求设备当前上电；投入使用前仍应验证发现和启动。
移除公网设备认证前需先禁用板卡。重命名公网 HTTPboot 板卡时也需先禁用，
按新 ID 重新配置设备认证后再启用。

新增和编辑租赁使用 `/qcl/rentals/new`、`/qcl/rentals/{id}` 独立页面。
顶部表单复用后台三列布局，备注单独占一行；下方日历填满内容区。
日历支持年、月、日视图和年月跳转：月视图拖拽连续日期，以最后一天的次日零点作为
结束时间；双击日期进入日视图，拖拽半小时格子选择具体时段，也支持键盘 Enter 选择。
展开“当日可用时段”可查看租赁详情或点击空闲窗口填入时间。年/月浏览不改变编辑草稿。
按浏览器时区显示，已取消租赁、待审核申请及当前编辑记录不计入占用。冲突拖拽会提示
并保留原有时间；按 Escape 或取消指针操作可放弃选择。实时占用变化会更新日历并禁用
冲突的保存操作，保留编辑草稿，服务器保存时仍以数据库锁重新校验。
前台“我的租赁”位于 `/account/rentals`，“租赁申请”记录位于 `/account/requests`，分别为独立页面。申请提交或取消后返回申请记录页面。点击“申请租赁”或设备目录入口进入
`/rental-request?board=设备ID` 独立网站页面，不嵌入个人工作台侧栏。工作台、“我的租赁”
和申请列表的申请入口均跳到同一页面；未登录时先登录并保留所选设备。旧
`/account/requests/new` 地址重定向到此页面并保留参数。申请页面占满一个视口高度，
左侧展示所选设备的介绍与参数，右侧为申请表、使用日历和固定的提交/取消栏。
较长的设备信息和日历在面板内部滚动，手机端上下排列。申请区后保留与其他前台页面相同的公共 footer，正常向下滚动即可到达。
当前账号固定为申请人，日历只展示匿名占用信息。实时占用推送会
禁用冲突提交并保留申请说明等草稿。

单击日期或半小时格会替换原选择，拖拽可重新多选。单击部分占用的日期会选择当天第一段
可用时间，可双击进入日视图细选；完全占用或过期格子显示灰色并禁用。
前台桌面内容、菜单栏和页脚统一使用窗口宽度的 80%，窄屏保留 16px 左右间距。
图标按钮统一为 42px 点击区域、18px 图标，默认透明无可见边框，悬停时显示背景。

除仪表盘固定明细表外，数据列表右上方提供布局图标菜单，在列表和卡片视图间切换。选择按列表保存到
浏览器的 `ostool.list-layout:*`，筛选、搜索、分页和操作按钮在两种布局中保持可用；
切换布局不触发额外 GET，也不会修改服务器数据。

管理后台位于 `/qcl/`。`OSTOOL_EDITION=local` 免登录且隐藏用户、角色和租赁入口；`public` 要求管理员登录和角色权限。
列表顶部统一左侧操作按钮、右侧搜索和过滤下拉框；系统设置以 Tab 区分网络、TFTP 和部署配置。
普通按钮、图标按钮、搜索框、单行输入和下拉框统一采用 42px 高度、8px 圆角和
16px 字号；多行输入沿用相同边框与焦点样式。表头与正文保持相同字号，采用中等字重、轻微背景色和细分隔线，与单元格统一水平间距。操作列统一为
带名称/悬停提示的图标按钮，图标为 18px；删除、释放等动作仍需确认。
开发板和租赁编辑页不显示重复的顶部返回操作；开发板删除放在底部取消、保存按钮左侧。

设备编辑的“设备恢复”组可配置释放后的幂等恢复命令。它在断电后运行，失败时设备继续保留、
运行状态显示释放错误；服务器重启也会在启用设备前执行。纯 RAM 启动可留空，有持久介质的设备
应配置并验证相应恢复流程。命令仅管理员可见，审计记录字段变更而不保存命令内容。
系统设置“网络与上传”支持会话/账号/全局存储、文件数、并发和超时限制；同一会话串行上传，
释放立即取消，下载采用流式传输。设备网接口决定仅供板端读取文件的私有下载地址及来源网段；不向普通用户返回该地址，修改接口后需重启。
仪表盘的运行状态、后台任务和运营状态均以顶部汇总卡片展示关键指标，下面为功能卡片和固定明细表，不显示布局切换。
实时连接状态统一在仪表盘运行状态中显示，不在各内容页顶部显示断线提示。连接中断或
运行状态同步失败时，保留已有数据，汇总不再显示服务正常，数据库、Redis 与审计状态
标为待重新确认；重新收到有效推送后恢复判断，单纯建立连接不会提前恢复正常状态。
开发板新增、编辑和系统设置均按“标题＋右侧横线”分组，直接放在背景上；系统设置使用顶部圆角标签页。
分组说明保留在标题下方，分组不添加叹号。具体配置项的额外说明统一放到标题右侧的叹号图标中，点击或用键盘打开，按 Escape 关闭。
占位文字只保留简短输入提示；格式、范围和生效说明不再常驻于底部或挤在占位文字中，辅助技术仍可读取控件描述。
布尔配置项统一采用“标题＋下方 Switch”，开关所在行与输入框同高，说明图标仍放在标题右侧。
列表选择、权限集合及协议同意等确认操作继续使用复选框。开关只修改当前草稿，保存流程不变。
所有多行输入框统一禁止拖拽缩放，协议编辑器保留工具栏全屏按钮和内部滚动。站点信息补充服务时间和隐私事务邮箱。
用户协议、隐私政策使用两个独立标签页，仅显示标题输入框和正文编辑框，预览、全屏、历史按钮放在正文编辑器顶部；正文占满剩余空间，可切换分栏预览、全屏编辑；
按 Escape 退出全屏。发布历史通过图标按钮打开，只展示当前文档的版本；可查看或载入为草稿，
载入不会直接回滚已发布版本。正文保持纯文本格式，与前台预览一致，不执行 HTML。
公网版账号及邮件策略在后台修改，保存到 PostgreSQL 并通过 SSE 生效。本地版系统设置保留站点信息、网络与上传（含审计保留策略）、TFTP 服务；隐藏用户协议、隐私政策、邮件服务、登录与安全，不订阅相关数据。
SMTP 密码和 Turnstile 服务端密钥通过后台加密保存，仅展示已配置状态；MFA 主加密密钥仍由部署配置管理。
右侧工作区填满视口高度，采用固定工具栏、独立滚动内容、固定底部状态栏的三段布局。
工作区直接使用与侧栏、标题栏相同的主题背景，不加外层卡片；功能卡片、工具栏与状态栏
统一使用 12px 圆角。状态栏直接贴到窗口底部，分页或按钮换行时，左侧底部系统设置区
自动同步其高度。审计日志放在主导航最后一项，底部系统导航仅保留系统设置。
列表没有数据或筛选无结果时仍显示固定表头，剩余内容区居中显示图标和“暂无数据”；
卡片模式使用同一空状态并隐藏表头。
全局框架左侧为导航，上方为固定标题栏；左上 Logo 区与标题栏使用相同高度和主题背景。
标题栏右侧依次为消息、主题、账号头像。消息从 SSE 的同步错误、释放失败和电源失败
中生成，不新增轮询接口；未读时显示角标，打开消息或点击“全部已读”清除本次
页面会话内的未读状态，提醒内容变化后重新标记为未读。这里不是持久化站内信或聊天功能。
前后台的操作成功、操作失败及资源加载错误统一通过顶部居中的弹出消息显示，可手动关闭，
登录页和对话框也使用同一提示入口；正文和底部按钮栏不再重复显示操作结果。
草稿状态、字段说明、诊断记录及需要用户选择后续动作的提示仍保留在对应内容中。
主题菜单支持明亮、黑暗、跟随系统，选择保存在浏览器并在刷新后恢复；系统模式随设备
偏好变化。公开版头像菜单包含账号、设置、网站和退出登录，本地版使用相同的账号菜单。
列表底栏支持每页 10/20/50/100 条和前后翻页。用户、租赁、申请、审计和会话历史由数据库
执行筛选与分页；设备、DTB 和活动连接等受当前设备规模约束的运行列表在 SSE 投影内分页。
所有分页底栏统一使用同一组件，包括会话历史、审计日志和设备文档；条数选择与翻页控件保持同高对齐。
列表首列统一为“编号”，按当前筛选结果连续计数，第二页从上一页末尾继续；每页条数或筛选改变时重新计算。
卡片视图显示同一编号并保留原记录标题，编号不替代设备、会话或用户的实际 ID。
个人中心的租赁、申请同样使用数据库分页，用户归属由服务端认证会话确定。
后台通过 `topics` 只订阅当前页面和公共标题栏所需资源，首次数据按资源就绪顺序逐项推送。
用户、租赁、申请的全局 topic 仅推送变更 revision；当前查询页通过 `listing` 推送。
搜索输入防抖 300ms；首次加载保留表头并显示骨架，翻页、筛选和重连保留已展示内容及编辑草稿。
日历仅查询当前设备、可见时间范围的占用，范围最长一年；用户选择按搜索加载前 50 项。
以上查询均通过现有 SSE 完成，不增加轮询或 mutation 后全量 GET。
筛选改变后返回第一页，实时推送保留当前页和滚动位置；记录删除后自动收敛到有效页。
开发板编辑和系统配置的保存、取消按钮固定在底栏，表单校验和并发修改提示继续生效。
开发板页面用紧凑筛选栏搜索名称、板型、MAC，并按板型、标签、状态筛选；
发现设备和虚拟设备从工具栏按钮打开；状态与常用编辑操作优先展示。

新建板卡的顺序为：填写电源配置 → 手动上电 → 选择发现的 MAC 或手工输入 → 保存。
上电只要求所选电源模块的必要参数，不要求板卡 ID、MAC、串口或 Session。
选择发现设备不会自动填写板型、电源或串口，保存前不会生成半成品板卡。
QEMU 使用已有虚拟设备，保存时校验虚拟设备 ID 与 MAC；允许先保存板卡配置，再完成发现或设备认证，避免认证配置依赖板卡记录而无法创建。

新增与编辑设备使用同一固定布局：基本信息、启动与绑定、手动/自动串口、U-Boot/TFTP 网络、电源管理和设备恢复。
配置项始终可见，启动方式、串口开关、电源模块和网络模式只控制对应输入框是否可编辑，切换时保留草稿。
宽屏下串口和启动网络配置并排显示，窄屏下按相同顺序排列。高级启动地址直接显示，不再折叠。
选择 axloader 后，手动串口开关及稳定标识禁用；可选启用“指定串口参数”并持久化保存，未启用时不配置覆盖，保存 `serial: null`。
指定参数优先于 axloader 上报，未指定时使用上报值或固件默认 115200/8N1。切回 U-Boot 保留编辑中的手动串口草稿。实际参数、端口、错误和 `SerialRuntimeStatus`
由会话的 SSE 展示；`serial_manager` 展示发现请求数与候选监听数。没有黑名单界面。
继电器配置继续保留，server 仅为启用配置在发现前排除其所有路径别名和 SN。

`httpboot` 是唯一 HTTP Boot kind；`uefi_http` 和 `boot_arch` 不再兼容读取，旧配置必须由部署人员修正。内核按不透明字节上传，server 不读取 ELF 架构。设备架构取自 axloader `/status` 的开放字符串 `arch`，发现列表和 `BoardEditor` 原样只读展示，包括 `future-isa` 等未枚举名称；离线或未发现时显示未知。`boardToFormState()` 和 `buildRequestPayload()` 不保留人工架构状态，选择 MAC 只改变绑定。

`BoardOta` 的上传、排队、任务历史和取消操作不按 CPU 架构隐藏；设备离线或未发现时
仍可先排队。服务端保存非空且不超过 32 MiB 的镜像字节、标签、长度及 SHA-256，
由 axloader 校验格式、`Machine` 和平台兼容性。实际 `ota` 状态缺失时不下发镜像，
任务保留可见的等待原因；设备返回 `503` 后，等待状态、能力或代次变化再尝试。

面板通过现有 `ota` SSE 资源展示 `Job.phase` 和安全处理后的 `Job.error`，原始设备错误不直接展示。
服务端日志保留 HTTP 状态、受限响应体及顶层 `{code,message}`；不可解码或截断的响应记为
`invalid_device_response`。`202` 仅表示暂存，
待新槽实际运行、确认且摘要匹配后任务才成功。`409` 延迟重试和网络错误的有限退避
由服务器处理；用户仍可查看错误或取消非终态任务。完整状态规则见
[装载器升级](axloader-network-control.md#22-装载器升级)。

开关机命令提交后由服务器持有，关闭页面不取消、不自动断电。实体板没有电源
反馈时，只显示命令完成。电源资源正在执行操作或属于使用中/释放中的板卡时，
冲突请求返回 409。Custom 命令只能按相同命令配置识别资源，不能推断不同命令
是否控制同一物理设备。Linux 管理端 Custom 命令限时 60 秒，超时终止并回收该
命令创建的进程组。既有 CLI 电源契约不变。

表单始终保留用户输入；其他客户端改变配置时显示冲突提示，由用户选择载入
服务器版本。列表更新不清空内容，重连不重置筛选与滚动。会话剩余时间是本地
时钟显示，不发起网络请求。普通“释放会话”等待清理完成后移除；“强制释放”需确认，
在设备失联、释放中或失败时仍可使用，不等待设备恢复，完成后移除活动会话并禁用开发板。
强制结束保留原失败记录且标为“管理员强制结束”，不代表已断电或已恢复硬件。
设备列表和卡片同样提供强制释放；有完整设备、会话及租赁管理权限的管理员可确认删除
占用中的开发板，同时强制结束会话并取消未结束租赁，使用历史保留。

列表工具栏的搜索提示仅显示在输入框内，过滤下拉框不附加底部说明；桌面默认搜索框宽
280px、过滤框宽 180px，窄屏自动换行。配置页保留对实际配置含义的说明。
系统设置只保留可在线保存的业务策略与服务设置；“登录与安全”替代原“登录与部署”，
部署地址、数据库连接、主加密密钥及数据路径等启动参数由 `.env` 管理，运行健康由仪表盘显示。
登录凭据保存在 PostgreSQL，暂时的刷新失败和推送断线不会触发重新登录；凭据失效或被撤销时才退出。
活动硬件会话仍在单控制器进程内；服务重启会结束这些会话，已保存的租赁时段和登录凭据继续有效。

## HTTP 接口

### 电源操作

`POST /api/v1/admin/power-actions`：

```json
{
  "request_id": "client-generated-unique-id",
  "action": "on",
  "power_management": {
    "kind": "zhongsheng_relay",
    "key": { "kind": "serial_number", "value": "relay-serial" }
  }
}
```

`action` 为 `on` 或 `off`，`power_management` 复用板卡配置的三个变体。
返回 `202`：`{ "id": "...", "action": "on", "state": "running", "message": null }`。
终态为 `succeeded` 或 `failed`，通过 SSE 的 `power_actions` 发布，也可单次查询
`GET /api/v1/admin/power-actions/{id}`。

同一服务器进程内，同一请求 ID 和相同参数返回原操作；改变参数返回 409。
请求 ID 长度为 1–128 字符。当前最多保留 4096 个操作，不丢弃幂等键，新请求超限
返回 503。进程重启后操作记录不恢复，查询返回 404；客户端不能自动重发未知动作。
开发板编辑页的分组保持纵向排列，组内宽屏使用三列，窄屏依次收为两列和一列；
标签和备注并排；串口开关、串口选择、波特率共用一行；网络模式与静态网络字段连续排列。
恢复命令等长内容按需独占一行。单行输入、下拉框和按钮使用相同控件高度。
电源管理把上电命令与“上电测试”、下电命令与“下电测试”分别左右组合，
电源模块、虚拟设备、继电器位于第一行，两组命令与测试按钮并排放在下一行。执行中只禁用电源操作按钮，
其他字段仍可编辑；请求发送时使用当时的配置快照。成功或失败通过顶部居中消息提示，
不再显示独立结果区域、查询或清除结果按钮。请求失败后仍通过 SSE 接收已有动作结果，
不会自动重新发送电源命令。

### SSE

`GET /api/v1/admin/events` 使用 `text/event-stream`。同一页面只创建一个连接。
服务端保活不包含业务更新；代理应关闭 SSE 缓冲并允许长连接。

```text
id: <epoch>:<revision>
event: snapshot
data: {"epoch":"...","revision":1,"kind":"snapshot","data":{"boards":[],"sessions":[],"loaders":[]}}
```

后续事件名为 `update`，信封字段相同，`data` 仅包含改变的资源集合。
集合键包括 `boards`、`runtimes`、`sessions`、`loaders`、`ota`（镜像和升级任务）、`virtual`、`dtbs`、
`serial`、`serial_manager`、`network`、`server`、`tftp`、`tftp_status`、`overview`、`power_actions`。
集合更新是该集合的完整替换；消失的实体表示删除。前端按稳定 ID/MAC/name
合并并复用未变化的对象，不重新挂载整张表或表单。

事件投影由单一发布器串行维护。业务模块提交后使相关集合失效，由发布器读取
对应所有者；没有后台循环调用全部 GET。快照和 revision 在同一同步边界取出，
订阅在读取快照前建立，读取期间发生的变化会进入后续更新，不会漏掉。

浏览器重连通过 `Last-Event-ID` 请求重放。服务器保留最近 256 条更新；epoch
不同、游标非法、超过保留窗口或消费者落后时发送新快照。客户端遇到 revision
跳跃会重新订阅获取快照。读取单个资源失败时发送 `{ "error": "..." }`，客户端
保留该资源最后一次成功的数据并展示错误。

Loader 的在线期限为 10 秒、设备记录保留 24 小时，到期会主动发布变化。
Linux 使用 inotify 监听串口设备节点、netlink 监听网卡/IPv4、systemd D-Bus
监听服务状态、SIGCHLD 监听 QEMU 退出；QEMU 串口连接变化单独通知。
这些监听需要新增 `notify`、`netlink-sys`、`zbus` 依赖；命令组清理由 `nix` 提供。
非 Linux 平台仍接收应用内部事件，系统级热插拔监听目前仅在 Linux 启用。

## 源码与构建入口

`ostool-server/src/api/` 实现后端接口，`src/persistence/` 实现数据库仓储；SQLx 迁移
放在 package 根目录 `migrations/`。`webui/` 使用 React/Vite 多入口：`index.html`

模拟器仅监听 `127.0.0.1:31000–31047`，无需开启 UDP 发现；正式部署不包含该 Compose 叠加配置。
48 台示例保留 4 台维护禁用设备，其余可申请；部分设备开放自动审批，示例“内核研发工程师”角色获得免审批权限。
登录、租赁时段冲突、审核、同板型并发、会话归属和到期撤销都由正式服务执行。
模拟器根据实际 HTTP 请求维护电源状态，断电后设备状态查询失败，恢复供电生成新的启动代次；
服务器通过正常设备轮询更新在线状态，离线显示受现有探测超时影响。模拟器重启后设备恢复供电；
网站启动仍沿用现有安全策略先对板卡断电，需要展示在线状态时在后台执行通电。
它不执行内核、串口或 OTA，相关请求会明确失败，不生成虚假的启动成功或串口数据。
`dev.sh stop` 同时停止模拟器；再次使用 `dev.sh demo` 恢复演示。

演示数据仅应导入可丢弃的数据库。旧宿主进程的开发目录不会被自动迁移或删除。
完整地址、证书及硬件容器映射说明见[服务器 README](../README.md#local-development-environment)。

## 已有开发板独立迁移

新服务只使用 PostgreSQL，不提供旧文件存储或启动导入。部署新版本后，使用独立的
`scripts/migrate-boards.sh` 导入已有板卡及引用的 DTB；数据库备份、停止旧服务、预检、
事务和冲突处理见[服务器迁移说明](../README.md#existing-board-migration)。

U-Boot 通过串口启动，无需绑定 MAC。切换到 U-Boot 后隐藏 MAC 选择器，保存时不提交
网络身份；切回网络启动时保留尚未保存的 MAC 草稿。

## 公开版租赁管理

租赁是用户对指定开发板在 `[starts_at, ends_at)` 之间的使用权，与现有短期会话租约独立。
同一开发板的非取消租赁不可重叠，相邻时间段允许。时间使用 RFC3339（建议 UTC），UI 按浏览器时区输入和显示。

- `GET /api/v1/admin/rentals`：数据库分页租赁列表，同步通过 SSE `listing` topic 推送。
- `POST /api/v1/admin/rentals`：新增，成功返回 201。
- `PUT /api/v1/admin/rentals/{id}`：修改未取消、未结束的租赁时间和备注，成功返回 204。
- `DELETE /api/v1/admin/rentals/{id}`：取消，保留记录，成功返回 204。相关会话通过原有流程终止、断电并清理文件。

新增/编辑请求：

```json
{
  "board_id": "rk3568-01",
  "user_id": "00000000-0000-0000-0000-000000000001",
  "starts_at": "2026-10-21T00:00:00Z",
  "ends_at": "2026-10-21T02:00:00Z",
  "notes": "测试使用"
}
```

时间冲突返回 409，无效时间/用户返回 400，未认证返回 401，非管理员返回 403。
普通用户的板型列表和会话创建按当前有效租赁过滤；到期后心跳不能续长使用权。
管理员保留维护访问。创建租赁不会自动上电；截止时开始正常释放，下一位用户需等待释放完成。
状态包括 `scheduled`、`active`、`expired`、`cancelled`，服务器在时间边界主动推送状态变化。
本地版不启用认证、用户、角色与租赁 API；这些接口返回 404，SSE 同样禁止订阅或查询相应数据。

前台首页的 hero 占满导航栏下方首屏，后续为设备、调试与 CLI 工作流介绍；设备目录使用
产品介绍、板型筛选和设备卡片组合。公开目录仍只包含设备 ID、板型、标签与启用状态。
文档页提供左侧菜单、中间正文和右侧本页目录，手机端改为可横向滚动的菜单；短页面的
页脚由完整高度布局推到底部。页面 HTML 含安全的运行版本启动配置，不等待数据库查询
后才显示页面；登录检查期间先保留完整后台或个人工作台框架，鉴权成功后才订阅私有数据。
用户名为全局唯一、忽略大小写的登录标识，与可选显示名称分开；登录接受用户名或邮箱，
注册和后台创建用户必须填写用户名。“会话管理 → 当前会话”（`/qcl/sessions`）展示当前使用用户与关联租赁时段，并支持释放会话。
开发板、用户、自定义角色和 DTB 列表的操作列提供启用/禁用快捷按钮，列表和卡片视图一致；
状态变更通过 SSE 更新，成功与失败使用统一弹出提示。占用中的开发板、当前账号、
内置角色及当前账号使用的角色保留原有保护，启用设备仍需通过串口和设备认证校验。
当前会话只突出一个主要状态：占用中、使用中、串口异常、释放中或释放失败；
终端连接用普通文字说明，自动串口绑定诊断只在详情中显示。释放阶段不显示无关的
连接或“等待设备”状态，释放错误仅关联到该错误所属的会话。

“会话管理 → 会话历史”（`/qcl/session-history`）是独立导航页面，查询 PostgreSQL 中的设备使用记录；使用 SSE 按筛选条件推送数据库
分页结果，支持表格、卡片、时间范围和结束原因筛选。记录保留分配时的用户名、用户 ID、
设备及租赁 ID，删除账号或设备不删除历史。详情显示最后心跳、请求释放时间、结束时间、
释放失败次数和最后错误。普通释放失败时记录仍为释放中，硬件清理成功后才结束；
管理员显式强制结束时无需等待硬件，历史记录保留失败和 `admin_forced` 原因。
正常关闭记录为 `server_shutdown`；异常中断遗留记录在下一次启动时标记
`server_interrupted`，结束时间为发现时间，不能据此推断实际断电时刻。
本地版保留设备会话历史，不展示用户及租赁字段。历史从本次升级开始记录，不补造以前
的使用记录。一个设备库只能由一个活动控制进程管理。

前台、登录/注册页与后台的同类控件统一由 `src/styles/controls.css` 管理尺寸、圆角、字体、边框、聚焦、禁用及错误状态；页面样式只调整布局，验证码输入框仅额外保留图片所需的右侧空间。

SMTP 密码和 Turnstile 服务端密钥在相应配置 TAB 中设置，只显示已配置状态，留空保留旧值，勾选清除后保存删除。密钥使用部署主密钥加密入库；主密钥自身仍在启动配置中管理。

账号与注册设置提供“用户名禁用关键词”“昵称禁用关键词”两个多行输入框，每行一个词或以逗号分隔。
匹配忽略大小写、全角及分隔符，采用包含匹配；每组最多 128 项，每项不超过 64 字。
空列表关闭该字段限制。设置使用已有版本控制和 SSE 更新，推送保留未保存草稿；保存后生效。
已有名称不改名不受影响，注册与用户改名由后端统一拒绝保留词，部署初始化管理员仍可创建保留名称。

设备列表和全局 `boards` 推送仅含设备摘要，不携带电源/恢复命令。
编辑页通过已有事件连接的 `board_editor_id` 和 `board_editor` 主题读取当前设备完整配置；
切换设备或离开编辑页会清除旧详情。保存和其他管理员变更仍由 SSE 同步，不新增轮询或保存后全量 GET。
远端变更保留本地草稿和焦点，提示冲突并允许载入服务器版本。
内部注册、绑定标识不返回浏览器；操作失败显示安全提示，并可用响应请求 ID 查询服务器日志。

## 统一角色权限与免审批申请

“用户管理 → 用户角色”新增和编辑均使用独立页面，沿用顶部工具栏、中间滚动内容、底部保存/取消。
权限矩阵采用分类列、能力选项、分组开关和全选布局，只包含当前项目功能。
支持权限搜索；操作权限自动补齐查看依赖，移除依赖时一并移除相关操作；未拥有的权限不可授予。
内置角色的权限只读，自定义角色权限与使用规则保存在 PostgreSQL。修改已分配角色会撤销其旧登录，
撤销受影响的凭据；不能修改自己当前使用角色的权限，不能维护权限高于自己的角色或用户。
后台页面、菜单、按钮、HTTP 和 SSE 均按角色能力限制，普通设备使用权限不会授予后台访问。

勾选“免审批使用设备”后可配置单次最长使用分钟数、每用户同板型预约并发台数、单次最短申请时长及板型范围。默认最短 30 分钟、最长 480 分钟、同板型并发 2 台；不同板型分别计算并发，人工批准的预约也计入对应板型。旧默认策略通过数据库迁移更新，自定义时长或并发策略保留。迁移沿用角色变更的安全机制，受影响账号需要重新登录，已经建立的普通预约不受影响。
设备新增/编辑页的“允许自动审批”（`allow_instant_use`）决定该设备是否接受免审批申请，现有设备默认关闭，不授予用户权限。
普通用户和高级用户统一从“申请租赁”选择开发板与可用时段后提交。普通用户等待审核；拥有 `board.instant` 的用户若同时符合设备开放范围、角色板型、最短/最长时长和并发限制，则自动通过，否则进入人工审核。没有直接领取入口，CLI 也不能跳过申请自动占用设备。

前台设备列表、详情、申请选项与租赁记录按当前用户资格在设备名称后显示“（免审批）”；设备未开放或不在角色板型范围时不显示。时长超出角色范围会提示并确认是否继续转人工审核。用户可在“我的租赁”中确认取消未开始的预约或提前结束正在使用的租赁，释放预约与并发额度，并停止对应会话。

同一开发板可按不重叠时段租给不同用户；已有当前租赁不影响未来时段分配，前一时段结束时间可等于后一时段开始时间。
管理员新增、编辑租赁的日历标注用户名、显示名称及起止时间。前台日历只显示合并后的匿名占用时段，不返回租赁 ID、租赁人、备注等信息；占用时段灰显禁选，切换日期仍可申请其他空闲时段。

自动通过会原子保存申请与正常预约租赁，完整保留用户所选起止时间；结束 CLI 会话或重启服务不缩短预约。前台根据实际返回的 `pending` / `auto_approved` 状态提示结果；免审批用户可在申请前查看设备开放状态和角色时长、并发限制，转入待审核时前后台申请记录均显示具体原因，免审批仅改变审批过程。本地版继续隐藏角色和租赁入口，免登录使用开发板。

## 设备认证

HTTP Boot 开发板编辑页的“设备认证”支持固定内网 HTTP 地址，也保留 HTTPS 与可选凭据、CA。
设备地址与独立凭据并排，CA 证书独占一行。
原生 axloader 不需要证书或 Bearer；已有凭据留空保留，保存后清空输入，远端更新保留草稿。
公网用户 HTTPS 与设备网络分离：两种模式均可启用 v7 UDP/HTTP 和只读 TFTP，公网版 TFTP 必须绑定明确的内网 IP。设备 HTTP 文件监听仅提供短时单文件凭据，不包含管理接口。两版均不恢复旧协议别名或文件后端。

axloader OTA 使用一行镜像选择框，右侧依次为上传镜像、删除镜像、下发升级。
点击上传后选择 EFI 文件即开始上传，框内按实际发送字节显示进度；保存成功后显示文件名，
仍可选择已有镜像。下发使用现有 SSE 的排队、传输、写入及确认阶段，显示动态进度条和
阶段文字，不估算字节百分比。上传鉴权、删除保护及取消升级流程保持原样。


## 设备文档与产品详情

后台“设备管理 → 设备文档”位于 `/qcl/device-documents`，选择设备后在
`/qcl/device-documents/:boardId` 独立编辑公开标题、简介、详细介绍、图片、亮点和参数。
查看需要 `devices.read`，编辑需要 `devices.manage`；本地版按原规则免登录管理。
字段均明确标为公开内容，设备运维备注、串口和控制命令不作为介绍内容。
文档保存在 PostgreSQL，保存后发布到网站；版本冲突会保留草稿并要求载入最新版本。
设备重命名保留文档，删除设备会同时删除文档。

设备列表采用更大的卡片，底部并排显示“查看详情”和“申请租赁”；本地版保留控制台操作。
详情地址为 `/devices/:boardId`，使用大幅设备展示、介绍、亮点和规格区块。
未填写的参数不做推测，未提供图片时显示明确标注的开发板示意图。
图片地址支持站内路径或 HTTPS 图片，不允许脚本和内嵌 HTML。
公开文档通过站点 SSE 同步，详情正文只订阅当前选择的设备，不向全部访客推送所有正文。

DTB 列表显示启用状态，修改与启用/禁用按钮直接展示，删除等收进更多菜单。禁用 DTB 后不能新增绑定或启动加载，开发板编辑器保留原选择并标明已禁用；重命名或替换内容保留状态。活动会话引用的 DTB 需先释放会话才能禁用。

设备列表以“通信端口”显示通信串口，另列“控制端口”显示继电器标识/路径、QEMU 设备或 Custom 控制方式；列表不暴露自定义电源命令。编辑器通过 SSE 获取启用配置的占用信息，选择冲突端口时显示占用方；禁用草稿可保存，服务端在启用时再次校验。

邮件服务支持自定义 SMTP、Brevo、Mailjet 和 Amazon SES。服务商模式自动采用 STARTTLS/587，
公共区配置启用状态、发件邮箱和名称，下方两列排列四家服务商卡片；选中卡片突出边框。仅自定义 SMTP 显示主机、端口和传输安全设置；SES 额外显示区域和端点。
各家凭据独立加密保存，切换不清除、不复用；每张卡片可测试当前草稿，凭据留空使用本家保存值。测试检查连接、TLS 和认证，不保存也不发送邮件，要求 `security.manage` 并执行管理员/IP 限流和 15 秒超时。
邮件服务页可设置全站小时额度，并分别调整所有用途共用的邮箱/IP 限制与注册额外限制。
注册是否必须先验证邮箱由安全页的“注册邮箱验证”控制。
投递记录中的“SMTP 已接受”只表示提交成功，不代表已到达收件箱；中断发送不会自动重试。

启用注册邮箱验证后，前台注册分为填写邮箱、验证邮箱、设置账号三步，第二步由服务端独立
校验验证码。修改邮箱或验证码、验证码过期会撤销当前步骤的验证状态；支持返回修改与冷却后
重发。验证码页只在输入框右侧显示重发倒计时，不显示总有效期；过期时提示重新发送；重发时在弹窗完成新的人机验证，成功后留在验证码页，不退回邮箱输入。用户名冲突或协议更新不会消耗邮箱码。未启用邮箱验证时省略验证步骤。

注册邮箱已被使用时，在完成人机验证后明确提示登录或找回密码，保留在邮箱步骤，不进入验证码页，也不创建假验证码或发送邮件。

本地调试在后台“登录与安全”开启“本地调试注册码”和“注册要求邮箱验证”，保持 public 版。
设置保存后立即生效，无需重启或 SMTP。邮件服务页显示调试提示，投递历史增加“调试注册码”列，
展示有效注册码与倒计时，模拟记录标为“本地模拟”。人机验证和限额照常执行；注册码只保留在
进程内存，消费、替换、过期后隐藏，重启后需重新获取。找回密码等其他邮件不模拟。

后台“登录与安全 → 人机验证方式”支持本地图形验证码（服务器自生成）和 Cloudflare Turnstile。
Turnstile 使用 Managed 组件，填写 Site Key、允许的验证域名并在下方设置加密的 Secret Key。
域名可用换行、空格或中英文逗号分隔。保存后用“测试已保存配置”完成实际验证；测试入口要求
`security.manage`，有未保存草稿时暂停测试。测试不自动提交设置，也不覆盖编辑草稿。
组件支持加载超时后重试、验证码过期、Cloudflare 超时和浏览器不支持提示。切换方式可直接测试，
公开页面 CSP 已允许 Cloudflare 官方组件；网站/后台登录、注册发码与密码恢复使用同一验证组件。

`.env` 仅保留启动依赖，业务配置不再作为启动覆盖值。邮件认证账号/API Key、密码/Secret Key、
Turnstile Secret Key 的输入框始终留空等待新值。邮件凭据的配置状态仅通过输入框占位提示展示，不另加右侧状态标记；留空保存保留，
勾选对应清除项后保存删除，替换与清除不能同时提交。凭据加密入库，API/SSE 不返回明文。
“网络与上传”新增审计保留天数：0 永久保留，1–3650 天；公网修改需审计管理权限，下次每小时
清理读取最新策略。“登录与安全”可配置允许访问后台的 CIDR 网段，必须包含当前管理员来源。
